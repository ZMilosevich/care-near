## Intended result
A calmer, readable, search-first landing with personal caregiver cards; preserve warm coral/teal identity and all working demo flows. This is a focused refinement, not a new app. Keep the current three brief booking steps (no added steps), with persistent concise summary. Design and implement the following as one coherent bundle.

1. Hero headline 2–3 lines at desktop, e.g. “Thoughtful care. / Close to home.” or “Short visits. / Trusted support. / Parents at home.” with modest 44–56px desktop and 36–40px mobile heading. Image no longer dictates an excessively tall hero. At 1280×800 and 1440×900 the complete primary search and secondary link are visible above fold. On mobile 390×844 search precedes image and is readily visible without scrolling a giant headline.
2. Remove hero Book a visit CTA. Primary action = Find care search, anchored inside copy column with strong width/alignment and labelled service/neighborhood fields. Only secondary hero action = See how it works, quiet text/arrow link. Search continues into existing discover filters. Deliberate yellow underline on one whole phrase with no stray positioning or overlap; can simplify to text-decoration with offset.
3. Readability throughout: body, form labels, service descriptions, caregiver metadata/badges, buttons, progress labels, status and summary info >=16px rendered. 18px for main paragraphs and older-adult update copy. Avoid blanket zoom hack; adjust component layouts/wrapping. Strong ink/muted on cream, verify WCAG AA normal text >=4.5:1, controls >=3:1; strong focus visible. Decorative map labels/tiny nonessential ornaments can be smaller only if no decision information depends on them. Do not claim certification.
4. Caregiver cards across landing/discover/profile/booking: actual photographic portraits instead of initials, rating + review count, next availability. Stock portraits are illustrative and represent fictional providers; use reliable permitted stock sources with local assets and source provenance in refinement report. No need image-generation here; keep existing hero. Clear compact shared label says ratings/availability/testimonial are sample data, not real claims. Missing image fallback and meaningful alt. Uniform top/card geometry, reserved badge block, flex footer anchored bottom, equal heights in landing rail even without certificate. Keep all details readable and functioning.
5. How it works: four concise steps with distinctive existing SVG icons, numbered markers and connecting line desktop; vertical connected flow mobile; tighter spacing. Do not introduce hover-only content.
6. Button hierarchy: per section main action solid, profile/explore links quiet text/arrow, no forest of outline rectangles. Book per caregiver stays clear. Apply to join leads recruitment section. Keyboard/touch hit areas >=44px.
7. Social proof: tasteful family testimonial block with short quote, named fictional first-name/persona and explicit “Illustrative family story” / sample indication; no fabricated real traction claims. Ratings in profiles also explicitly sample. Use warm editorial treatment.
8. Booking summary: retain live caregiver/price/date/time desktop sidebar. Add compact persistent mobile summary that doesn't cover fields/footer/keyboard; expandable details if useful, still showing caregiver/time/total while scrolling. Reuse existing price and state rather than duplicate formulas. Validate back navigation/consent/caregiver change still works. Consent copy affirmative and plain: recipient stays in control, choose what family can see, permission can change; no pretence production permissions exist. Keep required unchecked consent for someone else; show it in review.
9. Visits: visible distinct Pending, Confirmed, In progress, Completed states with short next-action copy, timeline and accessible local demo preview controls. A newly submitted request remains pending until explicitly simulating further state; no automatic actual booking/payment. Clear sample labels. Show coherent sample lifecycle data and progress, preserve completed summary/receipt/rebook. Add simple larger-text “For the person receiving care” view or equivalent obvious family/recipient switch sharing the same visit status, reassuring plain messages and contact access.
10. Phone access: easy prominent “Call someone” or “Call your contact” on visits and booking. No invented live caregiver/support number. Native dialog allows entering a trusted contact's number for this page session, explains user choice and local-only storage, then explicit tel: link opens dialer when user activates. Validate tel input against phone characters; never auto-call. If no number configured show setup state; button must do something useful. Don't add emergency clinical advice.
